## Step 1 — SQL (new migration `supabase/migrations/0005_trust_boundaries.sql`, forward-only; do not edit 0001–0004)

Principles: every DB entry point derives `org_id` from the entity, asserts active membership and role via `app.assert_role`, validates state and preconditions in the same transaction, and never accepts actor, org or hash claims from the caller. Postgres privileges, RLS and triggers must each independently stop the probe.

1. **Privileges (N-04, S-01, S-02):** `revoke execute on all functions in schema app from public;` `alter default privileges in schema app revoke execute on functions from public;` then grant explicitly. Make `app.transition_household`, `app.append_audit`, `app.assert_role` and the RLS helper functions **internal**: revoke from `authenticated`; the SECURITY DEFINER workflow functions still call them as owner. Decide and document whether schema `app` stays in `supabase/config.toml` `[api] schemas`; if it does, every function left executable by `authenticated` must assert membership/role on its first line. Run the Supabase advisor query for SECURITY DEFINER functions executable by `anon`/`authenticated` and paste its output into the PR.
2. **Households (S-01c):** replace the table-wide UPDATE grant with a column list (`label`, `status`, `assignee_user_id`, `source_tool_label`, `updated_at` — check the schema for the right set). Add `app.households_workflow_guard` (BEFORE UPDATE) that raises unless a sentinel set by the workflow functions is present (`perform set_config('app.workflow_fn', '1', true)` inside them; trigger checks `current_setting('app.workflow_fn', true) = '1'`). Protect `workflow_status` and `current_revision`.
3. **Audit (S-02, N-03):** `append_audit` becomes internal; `actor_type` is derived (`USER` when `auth.uid()` is not null; `SYSTEM` only when called from a service-role context, detect via `auth.role()`/`current_user`); `event_type` validated against an allow-list (mirror `packages/contracts` `AuditEventType`). Add `app.audit_chain_heads(org_id uuid primary key, last_seq bigint, last_hash char(64))`; `append_audit` takes the existing advisory lock, increments `seq`, includes `seq` in the hashed core, and writes `previous_event_hash = last_hash`. Add `seq bigint not null` to `audit_events` with `unique (org_id, seq)` and `unique (org_id, previous_event_hash)`. Add `app.verify_audit_chain(org_id)` that walks by `seq` and returns `(intact, broken_at, count)`.
4. **Freeze (S-03):** implement `app.canonical_json(jsonb) returns text` byte-compatible with `packages/contracts/src/canonical.ts` and `services/calculator/app/financial/canonical.py`: recursive, object keys sorted with `COLLATE "C"`, arrays in order, no whitespace, strings JSON-escaped identically, numbers rendered as the JSON text form the TS/Python tiers produce (decimals are already strings in our payloads; integers must round-trip). Prove equivalence with a fixture test: `fixtures/synthetic/canonical/*.json` hashed by Python (`canonical_hash`), TS (`canonicalHash`) and SQL (`encode(digest(app.canonical_json(...), 'sha256'), 'hex')`) must be identical. Then `freeze_snapshot` recomputes the hash and rejects mismatches, verifies `payload.household_id`, `tax_year`, `revision` against the household, and verifies every `payload.facts[].id` exists in `app.facts` for that household/org, is not superseded, and is `FACT_CONFIRMED` or `FACT_ASSUMED`. Port the `REQUIRED_FACT_KEYS_RMD` completeness rule from `apps/web/src/domain/freeze.ts` at least for the supported account types.
5. **Facts (S-05a/b):** revoke `UPDATE` on `app.facts` from `authenticated`. Add `app.confirm_fact(p_fact uuid, p_rationale text, p_evidence_ref text) returns uuid` (ADVISOR/COMPLIANCE; creates a new confirmed revision, supersedes the old; rationale ≥ 10 chars, evidence ref ≥ 3). Trigger: `superseded` may only change `false → true`; `verification_status` may change only inside workflow functions (same sentinel pattern).
